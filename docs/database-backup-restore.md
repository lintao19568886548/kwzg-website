# 官网数据库备份与恢复

本流程只适用于瞰维智管官网独立 MariaDB 数据库。不得连接、导出或恢复 `yizuw.cn` 生产数据库，也不得将备份文件提交 Git。

## 备份前检查

1. 明确环境、数据库主机、数据库名和维护窗口，至少由第二人复核目标不是业务生产系统。
2. 确认备份账号仅具所需只读与锁权限，应用账号不是 root。
3. 检查磁盘空间、MariaDB 健康、迁移状态和最近一次成功备份。
4. 备份输出到 Git 忽略且权限受限的目录；本项目约定本地演练使用 `.audit-private/` 或 `.audit-backups/`。

## 一致性备份

对 InnoDB 使用 `mariadb-dump` 的单事务模式，并包含例程、触发器、事件和字符集信息。密码通过受限环境或客户端配置注入，不写在命令行、脚本或日志中。

建议参数：

```text
mariadb-dump --single-transaction --quick --routines --triggers --events --default-character-set=utf8mb4 <数据库名>
```

备份完成后计算 SHA-256，限制文件权限，并使用组织批准的加密方式加密。建议每日增量/逻辑备份配合定期全量备份，保留周期由运营、法律和容量共同确认；至少保留多个跨日恢复点并定期离线演练。

## 恢复到新测试库

1. 再次确认恢复目标为新建的隔离测试数据库或新卷，不是现有开发库或生产库。
2. 使用与生产相同固定版本 MariaDB，创建 `utf8mb4` 数据库和非 root 应用账号。
3. 校验备份哈希，解密到受限临时目录，通过标准客户端导入新库。
4. 连接恢复库执行迁移状态检查；迁移脚本只允许单实例运行并使用 advisory lock。
5. 启动应用连接恢复库，检查 `/api/health`、预约记录、`lead_audit`、幂等索引和后台列表/详情。
6. 将恢复库中的管理员 Session 全部视为失效，清除 `admin_sessions` 后再验证新登录。
7. 完成后停止恢复环境并只清理本次明确创建的测试容器、卷和临时明文备份；不得删除其他项目卷。

## 完整性检查

- `knex_migrations` 与目标版本一致，重复迁移不破坏数据。
- `leads` 数量与备份记录一致，抽查测试线索字段与状态。
- 每条测试预约具有初始 `lead_audit`，外键关系有效。
- `idempotency_key` 保持唯一，表与连接字符集均为 `utf8mb4`，数据库会话时区为 UTC。
- 恢复环境中的后台仅在认证后可查看，列表手机号仍脱敏。

## 失败处理

恢复失败时保留错误代码和迁移批次，不记录 SQL 中的客户值或连接凭证。销毁失败的隔离恢复目标后从原备份重新开始；不要在原生产库上反复试错，也不要用 `db push`、清空数据或删除迁移记录绕过错误。
