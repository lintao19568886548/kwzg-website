## 本次统一规则

- 结构版心：1300px；使用双侧稳定滚动条槽和 `100vw` 安全边距，让视口左右边界在有滚动条时仍保持对称。
- 桌面安全边距：32px；手机安全边距：20px。
- 页头：82px；Logo 实测约 214 × 44px；导航 16 / 24px；预约按钮 116 × 44px。
- 1920px 首屏：左栏 500px、间距 56px、工作台 742 × 520px。
- 1920px 主标题 56 / 68px；1440px 主标题 54 / 66px；1024px 主标题 46 / 58px；移动端 38 / 48px。
- 首屏正文：桌面 18 / 30px，移动端 16 / 28px。
- 区块标题：38 / 50px；卡片正文不低于 16 / 28px；演示工作台高密度字段不低于 14 / 22px。
- 中文字体栈：`Microsoft YaHei`、`Microsoft YaHei UI`、`PingFang SC`、`Noto Sans CJK SC`、`Source Han Sans SC`、`Arial`、`sans-serif`。
- 只使用 400 与 700 字重，不使用小数像素字号、负字距、文字阴影、几何缩放或强制灰阶抗锯齿。

## 字体与静态渲染复核

- 字体发虚的主要原因不是首屏残留 GPU 变换：改前首屏可见文字的计算样式已经是 `transform: none`。真实问题是最终字体层曾优先使用 `Microsoft YaHei UI`、页头副宣传语只有 13px、首屏正文行高仍被旧规则覆盖为 32px，并且多套 1280/1360px 容器与旧字号规则并存，使文字在截图和窄版心中显得偏小、偏散。
- 本次把 `Microsoft YaHei` 提到字体栈首位，将常驻辅助文字下限统一为 14 / 22px，首屏正文统一为 18 / 30px，并让动效结束后移除 reveal 属性。含文字卡片不再在 Hover 时整体位移或缩放。
- `document.fonts.status = loaded`。
- `document.fonts.check('16px "Microsoft YaHei"') = true`。
- 正文计算字体栈第一项为 `Microsoft YaHei`。
- `motion=off` 下 518 个可见文字节点及其祖先扫描结果：残留 `transform/filter/opacity/will-change/zoom` 数量为 0（跳过仅在键盘聚焦时显示的 skip link）。
- 全站最小常驻辅助文字为 14px；工作台字段为 14 / 22px。
- 1920、1440、1366、1024、768、390 六档均满足 `scrollWidth === clientWidth`。
- 深蓝首屏对比度实测：主标题 14.92:1、正文 12.27:1；暖白区正文 5.57:1，均通过 WCAG AA 要求。
