# 官网预约线索后台操作与运维

本文档适用于瞰维智管官网独立线索后台。后台数据库与 `yizuw.cn` 生产系统完全隔离，不发送企业微信、短信或邮件通知。

## 标准本地启动与地址

唯一推荐的本地运行方式是 Docker Compose：

```bash
docker compose up -d --build
docker compose ps
```

Compose 会先等待 MariaDB 健康，再执行全部迁移，迁移成功后才启动 Nuxt Node Server。`GET /api/health/live` 只确认 Node 存活；`GET /api/health/ready` 会执行最小数据库查询，数据库不可用时返回 503。

容器内 Node 必须使用 `db:3306`；宿主机 Node 不能直接使用这个容器 DNS 名称。若确需在宿主机运行 Node，必须单独提供宿主机可访问、且未暴露公网的 MariaDB 端口，并在进程启动前明确设置 `NUXT_DATABASE_URL`。直接运行 `.output/server/index.mjs` 不会替你补齐数据库环境变量。

- 本地登录：`http://127.0.0.1:<KWZG_APP_PORT>/admin/login`
- 本地线索列表：`http://127.0.0.1:<KWZG_APP_PORT>/admin/leads`
- 正式登录：`https://yizuw.org/admin/login`
- 正式线索列表：`https://yizuw.org/admin/leads`

后台路由不进入公开导航或 Sitemap，并设置 `noindex,nofollow`。正式环境必须在 HTTPS 下运行。

## 创建首位管理员

完成数据库迁移后，在交互式终端执行：

```bash
npm run admin:create
```

Compose 环境可执行：

```bash
docker compose exec app npm run admin:create
```

命令会交互式读取账号和两次密码；密码不会回显，也不应作为命令行参数传入。密码须为 14–128 位，并同时包含大小写字母、数字与符号。成功时只显示管理员 ID 和用户名，创建事件会写入审计记录。

严禁把真实密码、密码哈希、Session 密钥或数据库密码写入本文档、代码、Git、终端命令参数或工单。

## 登录与退出

使用数据库中已启用的管理员账号登录。登录会话保存在服务端，浏览器仅持有 `HttpOnly`、`SameSite=Lax` Cookie；正式 HTTPS 环境设置 `Secure`。退出按钮会立即撤销当前会话。账号禁用或凭证版本变化后，已有会话会失效。

登录失败、成功和退出均写入安全审计，但不会记录密码。

登录页支持密码显隐、大写锁定提示、Enter 提交、数据库 503 独立提示和 Session 过期后返回原页面。“记住管理员账号”只在浏览器保存账号名称；取消勾选会清除该名称，绝不保存密码、Session、权限或线索数据。

## 工作台与每日处理顺序

登录后默认进入 `/admin`。顶部六个指标和三个任务区全部来自官网独立 MariaDB，不使用硬编码数据：

- 今日新增：按 `Asia/Shanghai` 当天 00:00 至次日 00:00 统计。
- 待跟进：状态为 `PENDING`。
- 今日应跟进：下一次跟进时间在今天范围内，且不是成交、无效或关闭状态。
- 已逾期：下一次跟进时间早于当前时间，且不是成交、无效或关闭状态。
- 已预约演示：状态为 `DEMO_SCHEDULED`。
- 本月已成交：只统计本月审计日志中真实发生的 `STATUS_CHANGED → WON`，不使用更新时间替代成交时间。

建议每天按“逾期 → 新预约尚未联系 → 今日跟进 → 普通线索”处理。每个任务区只读取有限条记录，“查看全部”会进入复用同一列表逻辑的 URL 筛选视图。

数据库异常时工作台显示失败态而不是数字 0；请先恢复数据库，再刷新页面。

## 未读线索

未读状态按管理员分别保存。当前管理员从未打开线索，或线索更新时间晚于其最后查看时间时，该线索为未读。打开详情后会标记已读；另一位管理员的读取状态不受影响。管理员自己完成状态、跟进或演示操作后，当前线索会保持已读，避免产生无意义红点。

侧边栏显示预约线索未读数、今日跟进数和逾期数；超过 99 显示 `99+`，为 0 时不显示。

## 查看和跟进预约

列表显示预约编号、提交时间、联系人、脱敏手机号、园区数量、来源页面、状态、负责人以及跟进时间。点击“进入详情”后可以：

1. 查看完整手机号并拨打或复制；完整号码仅在已认证详情页出现。
2. 按允许的状态流转修改状态，并填写必填的变更说明。
3. 追加电话、企业微信、现场沟通、视频会议或其他跟进记录，并填写跟进结果与下一步计划。
4. 设置或调整负责人，所有负责人变化写入审计。
5. 可选设置下一次跟进时间；逾期项目会以风险色提示。
6. 查看按时间倒序排列的跟进历史和只追加审计时间线。

原 `remark` 字段仅作历史兼容，不再作为唯一跟进记录。

桌面端从列表点击线索会打开右侧详情抽屉，并保留搜索、筛选、分页和 URL；浏览器后退或 Esc 可以关闭。手机端使用独立详情页，避免窄抽屉影响操作。

## 快捷操作与产品演示

线索列表和工作台任务支持以下快捷操作：

1. 拨打电话：认证后读取完整号码并生成 `tel:` 链接。
2. 复制号码：使用浏览器剪贴板；失败时显示可手动复制的完整号码，不写入日志。
3. 标记已联系：复用既有状态流转事务，从待跟进变为已联系。
4. 添加跟进：记录联系方式、内容、结果、下一步计划和可选的下一次跟进时间。
5. 预约演示：必须填写演示时间，可填写方式和备注；状态、演示字段与审计在同一事务内更新。

涉及无效或关闭等敏感状态时，界面会二次确认并要求原因。提交按钮在请求期间禁用，失败不会显示成功状态。

## 统一时间线

详情中的时间线按时间倒序合并官网提交、首次查看、状态变更、跟进、演示安排/改期和成交/无效/关闭事件。系统事件与人工跟进使用不同标签；长内容安全换行，大量记录按页加载。反复查看同一条线索不会无限新增“首次查看”记录。

## 修改与重置管理员密码

管理员可在 `/admin/profile` 输入当前密码、新密码和确认密码完成修改。密码须为 14–128 位并包含大小写字母、数字和符号，不能与当前密码相同。成功后所有有效 Session 都会撤销，需要重新登录；操作会写入安全审计。

受控终端可执行交互式重置：

```bash
npm run admin:reset-password
```

Compose 环境可执行：

```bash
docker compose exec app npm run admin:reset-password
```

命令只在交互式终端运行，账号和新密码交互输入，密码不回显、不作为命令行参数、不输出明文或哈希；成功后撤销该管理员全部 Session。

## Session 过期与手机端

管理 API 返回 401 时会跳转登录页并携带当前目标地址，重新登录后返回原页面。未提交的跟进内容不会写入 localStorage。退出后当前 Session 立即撤销。

768px 及以下使用抽屉导航，支持遮罩、Esc、焦点环路和背景滚动锁定；390px 线索列表改为卡片，仍可拨号、跟进和进入详情，主要触控目标至少 44×44px。

## 筛选、分页与导出

列表支持姓名或手机号搜索、状态、提交时间、园区数量、来源页面、负责人、逾期状态和排序；每页可选 20、50 或 100 条，并可一键清空条件。

“导出当前筛选 CSV”会先显示二次确认。导出包含完整手机号，只能在受控设备中使用。同步导出最多 1000 条；超过限制时应缩小筛选范围。CSV 使用 UTF-8 BOM，并处理公式注入风险。每次导出均写入审计。

## 审计

单条线索详情显示该线索的查看、状态变更、跟进和创建事件。记录包含操作时间、操作人、事件类型、前后摘要和请求 ID，不展示密码、Cookie、Session 或数据库连接信息。普通管理员没有修改或删除审计的入口。

## 数据库异常排查

数据库不可用时，管理接口应返回 HTTP 503 和结构化错误，不显示假数据或假成功。依次检查：

1. `docker compose ps --all` 中 MariaDB 是否为 `healthy`。
2. `docker compose logs db` 与 `docker compose logs app`，不得复制含密钥的信息到公开渠道。
3. `docker compose run --rm migrate` 是否显示迁移已经完成。
4. 应用是否加载 `NUXT_DATABASE_URL`、至少 32 字节的 `NUXT_SESSION_PASSWORD`、站点地址和受信任来源。
5. 数据库只连接 Compose 内部网络，3306 不应绑定公网或宿主机地址。

若预约接口返回 `DATABASE_UNAVAILABLE`，先确认浏览器所在端口对应的 PID，再确认该 PID 的启动命令；不要只检查另一个端口的健康容器。宿主机直接启动的 Node 进程即使页面可打开，也可能因为未加载 `NUXT_DATABASE_URL` 而无法提交。

数据库恢复后，连接池会重新建立连接，无需清空数据或重建数据库。

## 禁用管理员

当前第一版不提供网页端账号编辑，避免误操作。由受控数据库运维人员在变更流程中将 `admin_users.enabled` 设为 `0`，并递增 `credential_version`。现有会话会在下一次请求时失效。操作完成后应另行保留合规的运维记录；不得直接删除账号及其审计关联。

## 备份与恢复

- 每日使用组织批准的 MariaDB 备份工具执行一次 `--single-transaction --quick --routines --triggers --events` 备份，至少保留 30 天；每周把一个备份复制到独立、加密且访问受控的介质。
- 备份后校验文件非空并计算 SHA-256；监控最近一次成功时间、文件大小异常和校验失败。
- 不要把 `.sql`、`.dump`、日志或数据库数据目录放入 Git 或 `public/`。
- 恢复演练应在隔离环境进行：先恢复数据库，再运行迁移，最后执行健康、登录、列表、详情和审计检查。
- 恢复后核对线索、跟进和审计数量以及外键完整性，不使用真实客户数据进行公开截图。

本地隔离闭环与备份恢复演练命令：

```bash
npm run test:closed-loop
```

该命令使用独立 Docker 项目、独立数据库卷、随机测试凭证和虚构数据；会验证提交、初始审计、管理员登录、跟进、下次跟进、状态、时间线、重登、应用重启、数据库重启、数据库故障 503、恢复、并发幂等和备份恢复，最后销毁隔离容器与卷。审计结果保存在被 Git 忽略的 `.audit-private/lead-closed-loop/`。
