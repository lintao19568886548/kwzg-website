# 瞰维智管官方网站需求基线

> 本文持续记录已确认的官网需求。第 1～8 节保留 Stage 0 工程基线；第 9 节起记录 Stage 1 已锁定要求。Stage 1 视觉变量优先于 Stage 0 的临时配色。

## 1. 项目身份与隔离原则

- 项目名称：瞰维智管官方网站。
- 官网规划域名：`yizuw.org`。
- 既有业务系统地址：`yizuw.cn`。
- 官网必须作为独立工程和独立 Git 仓库建设。
- 官网开发、构建和测试不得访问、修改或影响 `yizuw.cn` 生产系统。
- 本阶段不部署、不修改 DNS、不操作生产数据。

## 2. 技术约束

- 前端框架使用 Vue/Nuxt。
- 业务代码和配置使用 JavaScript，不使用 TypeScript。
- 包管理器使用 npm。
- 项目应支持本地开发、生产构建、预览和代码检查。

## 3. 第一阶段范围

第一阶段只建立可运行、可检查、可继续演进的官网项目基线，不开始最终视觉设计。

### 3.1 页面路由

| 页面 | 路由 | 当前交付 |
| --- | --- | --- |
| 首页 | `/` | 临时运行验证页 |
| 产品能力 | `/products` | 路由骨架 |
| 解决方案 | `/solutions` | 路由骨架 |
| 客户案例 | `/cases` | 路由骨架 |
| 关于我们 | `/about` | 路由骨架 |
| 预约演示 | `/demo` | 路由骨架 |
| 隐私政策 | `/privacy` | 路由骨架 |

所有路由必须能够在桌面端和移动端正常打开，并包含基础页面标题与描述信息。

### 3.2 设计基线

全局设计变量必须至少包含以下品牌色：

- 深蓝：`#0D2A45`，用于主色、导航和重点文字。
- 砖红：`#A94B3C`，用于强调和行动入口。
- 暖白：`#F6F1E8`，用于页面背景。

同时建立字体、间距、圆角、阴影和内容宽度等基础变量，供后续视觉设计统一使用。当前样式仅用于验证布局和响应式能力，不代表最终视觉方案。

### 3.3 素材目录

公开静态素材统一放在 `public/assets/`：

- `public/assets/images/`：通用图片。
- `public/assets/logo/`：Logo 与品牌标识。
- `public/assets/cases/`：客户案例素材。
- `public/assets/wecom-qrcode/`：企业微信二维码。

当前阶段只创建目录说明，不放入真实客户资料或企业微信二维码。

### 3.4 工程能力

- `npm run dev`：启动本地开发服务。
- `npm run build`：生成生产构建。
- `npm run preview`：预览生产构建。
- `npm run lint`：执行代码检查。
- `npm run check`：顺序执行代码检查和构建。
- 使用环境变量配置站点 URL 和搜索引擎收录开关。

## 4. 基础 SEO

- 文档语言设置为简体中文。
- 提供全局站点名称、描述、主题色和 Open Graph 基础信息。
- 每个页面提供独立标题、描述、Canonical URL、Open Graph 和 Twitter Card 元信息。
- 阶段环境默认输出 `noindex, nofollow`，只有将 `NUXT_PUBLIC_INDEXABLE=true` 显式注入经过审批的正式环境后才允许收录。
- 本阶段不接入统计、广告或第三方追踪脚本。

## 5. 响应式与可访问性基线

- 桌面端和移动端均能访问所有页面。
- 页面采用语义化的页眉、导航、主体和页脚结构。
- 键盘焦点可见，颜色变量保留足够清晰的视觉层级。
- 内容容器和导航在窄屏下自动重排，不产生横向滚动。

## 6. 安全与数据要求

- 仓库不得包含真实系统账号、密码、密钥、Token 或生产配置。
- 仓库不得包含真实经营数据、未授权客户信息或真实客户案例素材。
- `.env` 文件不纳入 Git，仓库只提供无敏感信息的 `.env.example`。
- 官网基线不调用 `yizuw.cn` API，不连接生产数据库。

## 7. 明确不在本阶段内

- 最终品牌视觉、完整文案和正式素材制作。
- 表单提交后端、CRM、短信、邮件或企业微信集成。
- 用户登录、业务系统单点登录或生产 API 接入。
- 域名解析、证书配置、服务器配置、部署与上线。
- 生产数据迁移、读取或修改。

## 8. 第一阶段验收标准

- 本地项目能够正常启动。
- 七个页面路由全部能够访问。
- 代码检查通过。
- 生产构建无错误。
- 桌面端和移动端均能正常访问，无明显横向溢出。
- 不包含真实系统账号、密码和经营数据。
- 未访问或修改 `yizuw.cn` 生产系统。
- 未部署上线，未修改 DNS。
- 验收报告最终输出 `STAGE_0=PASS`；如未通过，应输出具体失败原因。

## 15. Stage 1.1：真实系统功能与官网界面溯源审计

### 15.1 最高优先级约束

- 官网所有产品界面展示必须来源于当前真实系统 `https://yizuw.cn`。
- 允许对真实页面进行高保真视觉重设计，但不允许创造系统中不存在的功能、字段、按钮、状态、图表、数据关系、权限关系、业务计算或业务流程。
- 每张官网系统展示图必须与一个真实系统页面对应；不得把多个系统页面拼接后冒充一个页面。
- 如需组合展示多个能力，必须拆分为多个独立页面卡片并分别记录来源。
- 只有在 `docs/system-ui-source-matrix.md` 中审核为 PASS 的展示界面才允许进入官网。

### 15.2 只读访问权限与禁区

- 用户授权本轮只读打开页面、查看菜单、字段、表格、卡片、图表、筛选条件、导航关系并记录真实功能。
- 禁止新增、编辑、删除、提交表单、审批、收款、核销、结转、财务处理，以及操作设备、门禁、访客、车辆、工单、角色、账号、权限或系统配置。
- 禁止自动化批量请求和压力测试；访问保持单页、人工节奏。
- 如出现登录页，必须暂停并由用户本人手动登录；不得要求用户把密码粘贴到代码、项目文件或对话中。
- 真实账号、密码、客户数据、租金、欠费、合同、手机号等生产信息不得进入代码、文档、终端历史、公开资源或 Git。
- 本地脱敏参考截图只能进入 `private-reference/yizuw-ui/` 等 Git 忽略目录，不得进入 `public`、`assets` 或提交；未脱敏原图完成复核后删除。

### 15.3 溯源范围与判定

- 重点核验经营总览、园区与空置厂房、招商管理、合同与财务、设备管理、运维管理、车辆与访客、员工与组织。

- 每项必须记录官网位置、展示名称、真实菜单、真实页面或路由、字段、按钮、状态、数据关系、视觉美化内容、是否新增不存在内容和 PASS/FAIL 结论。
- 只有菜单、空容器或未完成页面的能力不得作为成熟功能展示。
- 无法找到真实来源的页面必须从官网展示中删除；字段、按钮、状态或流程不准确时必须修正后复核。
- 展示使用脱敏且逻辑自洽的演示数据，不直接复制生产数据截图。
- 每张系统展示统一声明：“本界面基于瞰维智管现有功能进行视觉优化展示，使用演示数据，具体界面以实际交付版本为准。”

### 15.4 AI 能力边界

- AI 招商匹配只能位于独立“规划能力”区域并标注“规划中”。
- 不得放进真实系统截图，不得制作成可操作的已上线页面，不展示虚构匹配结果或执行记录，也不得使用已上线标签。
